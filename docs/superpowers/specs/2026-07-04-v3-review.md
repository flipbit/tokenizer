## Summary of Changes

These 31 commits complete two major work streams: (1) addressing all actionable findings from the prior v3 review (ReDoS timeout, eviction lock, Clear() fix, dead code removal, TokenizeCore extraction, leaveOpen fix, etc.), and (2) implementing the engine cleanup and async support spec — narrowing `ITokenizationEngine` to a single method, stripping redundant verbose logging, refactoring `TokenMatcher` via `MatchCore` extraction, and adding real async APIs (`TokenizeAsync`, `CompileAsync`, `MatchAsync`) backed by a ring-buffered `TokenEnumerator` and a Begin/Continue/End cooperative engine split with no sync-over-async.

## Strengths & Weaknesses

### Strengths

- `src/Tokenizer/Enumerators/TokenEnumerator.cs:362` — Ring buffer with CRLF normalization during bulk fill handles `\r\n` split across read boundaries correctly, moving normalization from per-character to per-chunk
- `src/Tokenizer/Tokenization/TokenizationEngine.cs:57` — Begin/Continue/End cooperative async split preserves zero overhead for the sync path while enabling real async I/O at buffer refill boundaries
- `src/Tokenizer/TokenMatcher.cs:170` — `MatchCore<TResult>` generic extraction eliminates duplication between typed and untyped match paths
- `src/Tokenizer/Enumerators/TokenEnumerator.cs:205` — First-char fast path in `TryMatch` skips `EnsureBuffered` for the vast majority of input positions
- `src/Tokenizer/Tokenization/ResultBuilder.cs:144` — HashSet-based `BuildUnmatchedTokens` eliminates prior O(T²) linear scan
- `src/Tokenizer/Validators/MatchesRegexValidator.cs:26` — ReDoS timeout properly applied to both regex-using components

### Weaknesses

- `src/Tokenizer/Tokenizer.cs:371` — Async tokenization path (`TokenizeAsyncCore`) is significantly less observable than sync: no log scope, no diagnostic summary, no required-missing warnings
- `src/Tokenizer/Enumerators/TokenEnumerator.cs:108` — `reader.Peek()` after `Read` can return -1 prematurely for non-buffered readers, incorrectly setting `readerExhausted`
- `src/Tokenizer/TokenMatcher.cs:356` — `encoding` parameter silently ignored in `MatchAsync(Stream)` — always decodes as UTF-8

## Security Review

**Security Posture:** LOW RISK

The prior HIGH-severity ReDoS issues have been properly fixed with 1-second timeouts. The primary remaining concern is `MaxInputLength` not being enforced on async paths, allowing memory exhaustion via unbounded `GrowBuffer` calls. The `AllowStreamBuffering` option provides good protection for `Stream` inputs but is not checked for `TextReader` inputs. Dependency surface remains minimal (Microsoft first-party only).

## Performance Impact

**Volume Assumptions:** WHOIS parsing: 50-200 templates, 500-5K char input, 100-1K calls/sec. Log parsing: 1 template, 100-2K chars, 1K-10K calls/sec. [UNCONFIRMED]

**Performance Impact:** NET POSITIVE

The ring buffer replacing the pushback queue improves cache locality in the inner loop. The first-char fast path in `TryMatch` avoids unnecessary buffer fills. HashSet-based unmatched token detection eliminates O(T²) scanning. The Begin/Continue/End split adds no overhead to the sync path. Two allocation concerns: staging buffer allocated on every `FillBuffer` call, and `frontMatterTokens` allocating via `.ToList()` on every tokenization.

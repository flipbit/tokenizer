## Summary of Changes

A complete v3 modernization of the Tokenizer library: nullable reference types, file-scoped namespaces, record types, async/streaming tokenization, a full compilation pipeline (Lexer -> Parser -> AST -> Template), diagnostic instrumentation, compilation caching, safety limits (DoS protection), cooperative Begin/Continue/End async protocol, 20+ new validators and transformers, DI integration, and comprehensive benchmarks. The library targets netstandard2.0, net8.0, and net10.0.

## Security Review

**Security Posture:** LOW RISK

The library has reasonable safety limits consistently enforced across sync and async paths. Two medium issues: ReDoS via user-supplied regex patterns (mitigated by 1s timeout), and hash-only cache key allowing theoretical collision-based cache poisoning. No injection, deserialization, or auth concerns.

---

## Multi-Tenant Isolation Review

**Isolation Verdict:** N/A

N/A — This is a text-processing library, not a multi-tenant system. Note: the static `DecoratorCache` in `TokenDecoratorContext` is a process-wide singleton that could cause cross-contamination if multiple Tokenizer instances register different transformers.

---

## Performance Impact

**Volume Assumptions:** Library processes text templates in request-handling paths; templates range from simple (3 tokens) to complex (50+ tokens with transformers).

**Performance Impact:** MEDIUM IMPACT

Key hot-path issues: `_parameters.ToArray()` on every transform/validate call (H1), regex recompilation per validation (H2), `Names.ToList()` per match iteration (H3), and byte[] allocation per cache lookup (H4). These fire in inner loops and are straightforward to cache.

## Observability Review

**Observability Verdict:** PARTIALLY OBSERVABLE

Structured logging is comprehensive with IsEnabled guards, but log levels are miscalibrated for library use. Per-call Information-level logs (M2, M3) will pollute consumer log output. HintProcessor logs "required hint missing" at Error for a routine data condition (H1). Diagnostic collector has no size limit (D2).

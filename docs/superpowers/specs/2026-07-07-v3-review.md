## Summary of Changes

The v3 branch is a comprehensive modernization of the Tokenizer library spanning 454 commits. Key changes include: a new multi-stage compilation pipeline (Lexer → Parser → AST → Binder), a diagnostics subsystem with alignment rendering and hint generators, async streaming tokenization with ring-buffered I/O, configurable safety limits for DoS protection, record-based immutability for options, 20+ new transformers/validators, performance optimizations (reflection caching, buffer reuse, LINQ elimination in hot paths), and dual-targeting netstandard2.0/net8.0/net10.0 with conditional compilation. Build passes clean (0 warnings, 0 errors), all 1334 tests pass, and formatting is verified.

## Strengths & Weaknesses

### Strengths

- `src/Tokenizer/Compilation/Lexer/TemplateLexer.cs` — Textbook compiler pipeline with clean Lexer → Parser → AST → Binder phase separation, each stage with a single testable responsibility
- `src/Tokenizer/Tokenization/TokenizationSession.cs:47-90` — Shared `ProcessChunk` between sync and async paths avoids the common trap of duplicating core logic
- `src/Tokenizer/TokenizerOptions.cs:18-35` — Record copy constructor deep-copies mutable lists, preventing shared-reference bugs; `WithTransformer<T>()` fluent API is clean
- `src/Tokenizer/Enumerators/TokenEnumerator.cs:302-413` — Ring buffer with CRLF normalization handles split-boundary edge case correctly, with watermark-based refill
- `src/Tokenizer/Diagnostics/IDiagnosticCollector.cs` — Zero-cost diagnostics via NullDiagnosticCollector singleton with consistent IsEnabled guards throughout

### Weaknesses

- `src/Tokenizer/Compilation/Binders/TemplateBinder.cs:256` — Re-parses front matter that FrontMatterBinder already processed, with silent-false fallback on unknown values vs FrontMatterBinder's throw
- `src/Tokenizer/Tokenizer.cs:131-196` — Sync `TokenizeCore` has no try/catch logging while async path has full exception handling
- `src/Tokenizer/Token.cs:39-111` — 13 mutable properties with `internal set` after construction; mixes data holding with assignment/transformation logic
- `src/Tokenizer/Diagnostics/Hints/PreambleNearMissHintGenerator.cs` — Dead code: `TokenMissed` events never pass preamble data, so hints are never generated

## Security Review

**Security Posture:** LOW RISK

Well-defended for a library. Regex timeout enforcement (1s) on both `MatchesRegexValidator` and `RegexReplaceTransformer`. MaxInputLength/MaxTemplateLength/MaxTokenCount/MaxIterations all enforced. Deep copy on options. Type-constrained reflection via DecoratorRegistry. Two Medium findings: async `TokenMatcher` buffering paths (`BufferTextReaderAsync` and `EnsureSeekableAsync`) read unbounded data into memory before `MaxInputLength` is enforced, enabling OOM before safety limits kick in.
